# Cloud assistant verification and limitations

## Verified

- Clean-source backend regression suite: **1288 passed**. Payment, auth, audit,
  owned-record access, financial number/action guards and packaging checks included.
- Next.js web: **197 tests passed**, TypeScript and ESLint passed.
- Legacy Vite frontend: **142 tests passed**, TypeScript passed.
- Next.js and Vite production builds completed. Next CSP hashes regenerated by the build.
- Desktop and mobile headless Chromium against the real local built Next app/API,
  under production-like CSP: connection controls, consent, rejected key, successful
  mocked Groq connection, guarded reply, quota countdown, memory-only key, removal,
  reload clearing and no browser console/CSP errors.
- Repository scanner and Ruff passed. Source Space app syntax compiled; pinned model
  revision and package version metadata checked against public HF/PyPI metadata.

**All provider HTTP in automated tests was mocked. No real key, token, charge or GPU
allocation was used. A passing integration test is not a real model quality test.**
Browser screenshots intentionally display “mocked” responses, not a deployed AI demo.

## Cloud contract coverage

- Native Gemini generateContent and Groq chat-completions shapes; secrets only in
  authentication headers, never URLs or model input.
- Gradio HTTP job submission and SSE complete/error handling for the pinned runtime.
- Exact HTTPS *.hf.space operator origin validation; no user-entered inference URL.
- Missing HF setup is explicit, not a generic offline answer.
- Rate limits, rejected permissions, missing model, malformed responses, timeout/
  transport error mapping; raw upstream errors never returned or logged by the adapters.
- Retry-After numeric/date, structured Google RetryInfo, known ZeroGPU HH:MM:SS format;
  malformed or absent times remain unknown. No invented daily reset or automatic retry.
- BYOK connection test authenticates and requires provider consent. It sends only a
  synthetic ping. A valid key activates only in this client session.
- Request-scoped keys do not mutate the global assistant or appear in response/audit
  details/prompt/history/storage. Recognised accidentally pasted key patterns are redacted.
- Conversation is bounded, role-restricted, masked and explicitly untrusted; it cannot
  become financial source data, tool permission or task confirmation.
- Managed cloud output failures do not silently substitute canned chat. A safety
  rejection is explicit. Existing payment safety refusals/engine plan cards remain.
- UI keeps conversation on provider switch/removal; clears credentials on reload,
  unmount or signed-in user boundary. No automatic paid-provider failover.

## Not verified / not promised

- Your HF account eligibility, Space build/startup, live GPU execution, actual quota
  ownership, queue time or free availability. Deployment scaffold requires real testing.
- Real Gemini/Groq API access, model access or billing tier. Model IDs are configurable
  because providers can retire or restrict them. “Connection verified” requires your key.
- Natural-language quality, multilingual safety completeness, broad semantic accuracy or
  financial advice reliability. Regex masking and output checks are defence in depth,
  not a proof against every hallucination, PII pattern or multilingual attack.
- Unlimited free inference, exact wait time when upstream does not supply one,
  guaranteed recovery when a timer reaches zero, or guaranteed cancellation/refund for
  inference already in flight when a caller disconnects/times out.
- Model server deployment or signing into HF on your behalf. No local LLM weights added.
- Production readiness: needs HTTPS, provider account configuration, tenancy/security
  review and real service testing. The demo uses synthetic data only.
