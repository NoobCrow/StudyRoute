# Execution evidence (sandbox operation logs)

Generated by `python -m app.scripts.export_evidence`. Everything here is **synthetic**: simulated
accounts, simulated providers, simulated settlement. No real money moved and no real data is used.

| File | What it shows |
|------|---------------|
| `sandbox_operation_log.txt` | The 14-step demo run against the API, one line per check, OK or FAIL |
| `audit_log.json` | Every audit event in order, each with `prev_event_hash` and `this_event_hash` |
| `audit_verify.json` | The hash-chain verification: status, events checked, head hash |
| `payments.json` | The payments created, with their state timeline and UETR |
| `bank_network.json` | The simulated interbank transfers (national and international) with every hop, the simulated messages and the double-entry journals, plus the trial balance and mirror-account check |
| `smart_escrow.json` | The smart escrows (schedule, state, the contract call log with its hashes), the simulated chain's status, the audit anchors written to it and the check that the database still matches the chain |
| `tamper_demo.json` | Verify after one audit row was edited behind the application's back (FAIL at that sequence), and after it was restored (PASS). Only present when run with `--tamper` |
| `docker_run.txt` | A real `docker compose` run (Docker 29.1.3, Compose 2.40.3, Ubuntu 24.04 VM): container health, the read-only and capability-dropped settings, the smoke script, the 14-step demo and the browser audit. Recorded by hand from that run; **this command does not regenerate it** |
| `docker_telemetry_capture.txt` | A packet capture of the real backend container: ONNX Runtime's Microsoft telemetry was found phoning home, switched off, and re-checked (0 packets to a public address, with the demo and 130 s idle). Recorded by hand; **this command does not regenerate it** |
| `security_2026-10-18/` | The raw output of the six security tools on 18 Oct 2026 against throwaway lab databases and the current code: `attack_probe.txt` (146 of 146 defended, including the bank review desk), `brute_probe.txt` (8 of 8), `leak_scan.txt` (all clear, 50 checks), `mitm_probe.txt` (14 defended, 0 failed), `assistant_probe.txt` (42 of 42), `browser_audit.txt` (48 of 48 in real Chrome under the production CSP). Written by `scripts/security/`; see `docs/SECURITY_TESTING.md` |
| `ai_evaluation.json` | The trained reader against the rule-based reader on held-out, natural and blind data: routing, values, attacks blocked, harmless blocked, latency. Written by `ml/evaluate.py` (readable version: `docs/AI_EVALUATION.md`); **this command does not regenerate it** |
| `ai_backbone_ablation.json` | The six base models that were fine-tuned and compared on the dev split. Written by `ml/collect_ablation.py`; **this command does not regenerate it** |
| `ai_rl_evaluation.json` | The reinforcement-learning dialogue policy against the old behaviour and the hand-written rules on simulated test conversations, with the reward-sensitivity runs and the SHA-256 of the policy it describes. Written by `ml/rl/evaluate_rl.py` (readable version: `docs/AI_RL_EVALUATION.md`); **this command does not regenerate it** |

To reproduce: start the API with fresh demo data, then run the command above.
